# Pink Mall — look renders

Всяка кураторска визия е **един готов реалистичен прозрачен рендер на сестра**.
Браузърът не сглобява тяло, глава и дрехи — рендерът вече ги съдържа.

## Структура

```
assets/pinkmall/looks/
  launch01/
    left.webp     ← цялата визия на лявата сестра
    right.webp    ← цялата визия на дясната сестра
  summer01/
    left.webp
    right.webp
```

## Изисквания към рендера

| | |
|---|---|
| Формат | прозрачен **WebP** (PNG работи като fallback) |
| Канонична рамка | **1000 × 1500** (2:3) — същата като `viewBox`-а на картата |
| Съдържа | тяло, глава, коса, дрехи, обувки, чанта, очила, аксесоари |
| Кадриране | цяла фигура, центрирана хоризонтално, стъпалата долу |

Ако рендерът е с друго съотношение, задай реалните `width`/`height` в
`render` — контейнерът и `viewBox`-ът се нагласят автоматично. Картите
обаче са изчертани срещу конкретната рамка, така че при смяна на
съотношението трябва да се прекалибрират.

**Не слагай тук изолирани продуктови снимки.** Те са друг тип асет и се
подават през `product.productImage`.

## Липсващ рендер

Ако файлът липсва, само тази фигура показва „LOOK RENDER COMING SOON".
Сцената, копитекстът, sister label-ът, каруселът и другата фигура
продължават да работят, а зоните на липсващата фигура се изключват.

## Нова колекция

1. Изнеси двата рендера в нова папка (напр. `summer01/`).
2. Добави `summer01` ключ в `PINK_MALL_LOOKS`.
3. Опиши продуктите и `map.hitPath` / `map.highlightPath`.
4. `PinkMallStage.setLook('summer01')`.

Hero-то не се пипа.

## Калибриране на картите

В конзолата: `PinkMallStage.debug(true)` → границите на картата, hit
зоните и ID-тата стават видими, а всеки клик върху рендера логва
нормализирани координати (`[PinkMall map] left  x: 428  y: 611`).
С тях се чертаят `hitPath` / `highlightPath`.
