# PINK MALL — Workstation 2.0 Build Packet

Status: **PRE-BUILD SPECIFICATION — NO CYBERNINJAS RUNTIME CLAIM**

This packet translates Contracts 05–08 into a public-safe implementation target for
the first CyberNinjas Workstation build. It does not claim that the graph has been
created.

## 1. Build target

Create:

**PINK MALL HQ / Master Station**

followed by the reusable pattern for:

**one separate campaign station per campaign**.

The first implementation target is the station architecture, not a live
commercial campaign.

## 2. Logical graph

The logical flow is:

```
INPUT
  ↓
CONTEXT
  ↓
PHOTO ARCHITECT
  ↓
IMAGE
  ↓
QA
  ↓
VIDEO (optional)
  ↓
COPY / ADAPTATIONS
  ↓
FINAL
  ↓
APPROVAL
```

This is a **logical contract-level flow**, not a claim about CyberNinjas node
names. The exact CyberNinjas node implementation remains an open decision.

## 3. HQ / Master Station surface

The HQ surface must provide visibility for:

- CURRENT STORY
- ACTIVE CAMPAIGNS
- WAITING FOR APPROVAL
- recent winner / social signals
- creative-fatigue visibility
- NEXT 3 IDEAS
- credit and cost visibility
- EXPERIMENT LAB
- WORLD / STORY MAP
- REJECTS & LEARNINGS
- simple creative overview with expandable technical/audit detail

HQ is a view/coordination surface. It does not become a source of truth.

## 4. Campaign station checkpoints

Every campaign station follows:

1. **CONCEPT**
2. **IMAGES**
3. **VIDEO** — optional
4. **FINAL**

The campaign station may be constructed after the campaign idea has received
the required owner approval. Construction itself grants no spend or publication
authority.

## 5. IMAGE exploration gate

The normal first image exploration is:

- 2–3 variants;
- meaningfully different directions;
- no product drift;
- no identity substitution.

The number is not a universal output quota for the whole campaign.

## 6. Product / identity locks

The station may READ Product Truth and Human Truth.

It may not rewrite either.

Product Truth comes from the Product Onboarding / canonical repository
authority.

Human Identity comes from the Avatar Skill.

Generated media is campaign media/candidate output; it never becomes canonical
commerce media merely because generation succeeds.

## 7. Candidate and QA lifecycle

Logical output states:

```
PROPOSAL
  ↓
GENERATED_OUTPUT
  ↓
CANDIDATE
  ├── QA PASS ──→ eligible for next gate
  ├── QA FAIL ──→ REJECTED / REWORK
  └── QA UNRESOLVED ──→ STOP / REVIEW
```

The final commercial state remains separate:

```
CANDIDATE → APPROVED → PUBLISHED
```

Neither generation success nor QA PASS is commercial approval.

## 8. Provenance minimum

Each executable output should be traceable to:

- station reference;
- campaign reference;
- checkpoint;
- output reference;
- parent output reference when applicable;
- execution provider;
- execution model;
- output class;
- QA disposition.

Real private operational records must not be placed in this public repository.

## 9. Authority boundaries

The workstation has no independent authority for:

- Product Truth;
- Human Identity;
- Story State transition;
- approval;
- publication;
- spend;
- autonomy;
- raw social metrics;
- Super Brain durable learning.

If an underlying authority is unavailable, the station must surface unavailable
state rather than invent a value.

## 10. Budget / model routing

Budget modes are:

- ECONOMY
- STANDARD
- PREMIUM

No numeric ceiling is defined here.

Claude selects the generation model. The provider and model are not frozen by
this packet.

A model choice is not approval, and a budget-mode label is not a numeric spend
authority.

## 11. Video gate

Video is optional.

If video is used:

- an approved image checkpoint should provide the appropriate visual starting
  point;
- video must preserve Product Truth and Human Identity;
- video QA remains separate from commercial approval;
- failed video remains traceable and may not silently replace an approved still.

## 12. Copy / adaptations

Copy/adaptation work may produce:

- campaign copy;
- social adaptations;
- format variants;
- site/banner adaptations.

Copy may use only authoritative product facts plus approved brand/campaign
context.

The station must not invent product facts, prices, sizes, availability or
publication status.

## 13. Approval boundary

The station may prepare a final package for owner review.

The owner approval is the commercial gate.

Silence is never approval.

Auto-publish is not authorised by this packet.

Additional paid correction spend after failed QA requires owner review under
Contract 06.

## 14. Super Brain boundary

Super Brain may supply semantic context or learning when available.

It is never allowed to overwrite:

- Product Truth;
- Human Identity;
- approval;
- operational campaign state;
- raw metrics;
- publication state.

A single viral result is not automatically durable learning.

## 15. HQ relationship

HQ observes and coordinates campaign stations.

It must not collapse:

- candidate;
- QA;
- approval;
- publication

into a single generic "done" state.

Conflicting authoritative states must be surfaced, not silently resolved by HQ.

## 16. CyberNinjas implementation check

Before creating the actual graph, verify:

1. authenticated CyberNinjas account is available;
2. Workstation 2.0 is accessible;
3. graph/node editing is available;
4. node types needed for the logical graph exist;
5. nodes can be configured programmatically or reliably through the available
   interface;
6. image generation can use the available CyberNinjas model routing;
7. outputs expose sufficient metadata for provenance;
8. QA checkpoints can be represented without turning QA into approval;
9. station duplication/template capability is available;
10. the resulting graph can be inspected and reproduced.

**Do not infer any of these capabilities from marketing copy alone.**

## 17. Current access finding

At the current verification point, the public CyberNinjas Workstation route
redirects unauthenticated users to the sign-in page. The connected Opera
browser tab reaches `/home/workstation` but exposes no usable workstation graph
through its accessibility tree.

Therefore this packet is ready for the next live build step, but **no graph
creation is claimed until authenticated Workstation access and the actual node
surface are observable**.

## 18. Build exit gate

The build is not considered started merely because this packet exists.

The first live-build exit gate requires evidence of:

- the actual CyberNinjas Workstation surface;
- a created PINK MALL HQ / Master Station;
- the logical station structure represented in actual nodes;
- no invented authority;
- no private data leakage;
- successful independent inspection after creation.
